# Premium web design

## Activation rules

Apply when explicitly invoked or when the user requests web design, a visual redesign, responsive layout, or visual polish. Do not activate for unrelated backend work. A planning request authorizes a design plan only, not implementation.

## Instructions

1. Read root `AGENTS.md` and inspect the current stack and brief. Identify required content, pages, interactions, and constraints. Do not add features or substitute frameworks.
2. Inspect the user's visual references. Write a concise reference analysis covering hierarchy, grid, whitespace, type scale, palette, imagery, and distinctive details. Map observations to the requested interface. Explain inaccessible references and request what is essential before claiming a match.
3. Define a coherent direction: type hierarchy, spacing rhythm, content width, responsive behavior, color roles, and image treatment. Prefer existing tokens and components. Premium quality comes from composition and consistency; do not default to gradients, glass panels, oversized text, or decorative animation without support from the brief and references.
4. Use the supplied copy and permitted assets. Do not invent customer logos, testimonials, statistics, product capabilities, or marketing sections. Label temporary placeholders when they are necessary and within scope. Check asset usage rights; do not buy assets or install paid services.
5. When implementation is authorized, build the requested scope with semantic HTML and reusable components appropriate to the existing stack. Keep reading order meaningful. Specify hover, focus, active, and disabled states only for controls present in the brief.
6. Inspect actual rendered output and refine against references. Use the visual audit skill for delivery. Do not treat a successful build as visual validation.

## Quality checks

- Compare reference and implementation at matching viewport sizes; check hierarchy, proportions, alignment, spacing, type, and imagery.
- Inspect narrow mobile, tablet, and desktop layouts; check wrapping, content-driven heights, image crops, and horizontal overflow.
- Verify keyboard focus, semantic headings, readable contrast (WCAG AA targets), usable touch targets, and zoom/reflow.
- Confirm every visible section and interaction belongs to the brief; list any intentional reference deviations.
- Report executed checks and unresolved issues separately. If no app exists, supply a direction or plan without inventing browser results.
